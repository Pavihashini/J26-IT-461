# Root & Reuse — Proactive Food Waste Prevention System

A React frontend-only prototype for the final-year research project **“A Proactive AI-Based Food Waste Prevention System for Restaurants.”** The interface follows the three-component architecture in the supplied presentation and includes the approved Cost & Savings Calculator extension inside Component 2.

## Requirements

- Node.js 18+ (Node.js 20+ recommended)
- npm

## Run locally

1. Extract the project ZIP.
2. Open a terminal in the extracted `food-waste-frontend` folder.
3. Install packages:

   ```bash
   npm install
   ```

4. Start the development server:

   ```bash
   npm run dev
   ```

5. Open the local URL printed by Vite (usually `http://localhost:5173`).

To create a production build, run `npm run build`. To preview that build, run `npm run preview`.

## Main interactions

- **Demand forecasting:** change the forecast date, adjust per-dish preparation quantities, and inspect combined ingredient totals. Shared ingredients are consolidated across recipe lines.
- **Inventory & waste risk:** select any ingredient to inspect its simulated risk factors and alerts. Switch between Risk Overview and Cost & Savings.
- **Cost & Savings:** filter recorded waste logs by day, 7 days, or 30 days; edit waste quantities and purchase unit costs; inspect cost rankings, category loss breakdowns, daily trends, near-expiry stock exposure, and adjust the hypothetical waste-reduction percentage.
- **Surplus bidding:** select a mock listing, place a bid higher than the current highest bid, and see the bid history update. A local countdown closes bidding; “End this demo auction now” allows immediate demonstration of the result screen.

## Important prototype boundaries

All restaurant records are illustrative mock data. Forecasts and inventory risk scores are not generated by trained models. AI-assisted recommendations are simple explanatory/rule-based examples. Cost and savings totals are calculated in JavaScript from the waste records. Estimated potential savings are not guaranteed savings; observed savings are unavailable because no before/after comparison dataset is included. Inventory value at risk is estimated separately and is not added to recorded waste cost. Bidding and timers are local React interactions—not WebSockets, a multi-customer auction, payment processing, a database, or a backend service.

## Presentation mapping

- **Component 1:** mirrors the demand data → dish-level prediction → ingredient quantity → preparation recommendation flow (presentation pages 8–13).
- **Component 2:** combines stock, expiry, forecast usage, and historical waste; displays low/medium/high risk and explainable alerts (pages 14–18). The additional Cost & Savings Calculator remains within this component as requested.
- **Component 3:** simulates a surplus listing, timed customer bidding, and highest-valid-bid-wins outcome (pages 19–22).
- The application uses the presentation’s affordable software-only approach and does not add a backend or hardware integrations (page 23).
